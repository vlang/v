Compile V directly to a WebAssembly binary through the SSA backend. No C compiler,
Emscripten, or external assembler is needed to emit the module. -prod optimizes SSA.
See doc/wasm.md for the supported features, host ABI, and embedding examples.

Usage:
  v -b wasm [-options] <target.v|target_directory>

The default output is <target>.wasm. An explicit -o path is used exactly.
The same binary works in Wasmer and browser/Node.js WebAssembly hosts; no separate
wasmer backend is needed. Pure functions need no imports. Printing and process exit
request WASI preview1 imports, which the instantiating host must provide.

Example:
  v -b wasm -o add.wasm examples/wasm/add.v
  node examples/wasm/add.mjs add.wasm
  wasmer run add.wasm --invoke add 20 22

Main-module scalar functions are exported by name; @[export: 'name'] overrides it.
Programs with main export the WASI entry point _start. Modules without main can be
instantiated as libraries. memory and __v_alloc are exported for host-owned buffers.
Declare host callbacks with @[wasm_import_namespace: 'host'] in a .wasm.v file.
Only called imports are emitted. The -os browser and -os wasi aliases select the
same wasm32 ABI; they do not supply host services or remove imports.

The standard C-only compiler automatically builds and runs a cached full compiler
for this backend. Use v -compile-backend wasm self to include it in the main
executable, or -all-backends to include every backend. A standalone compiler build
needs -compile-backend wasm or -all-backends.

For more general build help, see v help build.
