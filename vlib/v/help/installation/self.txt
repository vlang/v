Rebuild V with the passed options.

Usage:
  v self
  v self -prod
  v self -b fastc
  v -b arm64 self
  v -b arm64 self x2
  v -compile-backend amd64 self
  v -b amd64 self x2
  v -b amd64 -d amd64_only -o v_amd64 self
  ./v_amd64 self x2

Options:
  All other options are passed to the build command. (e.g. -prod)
  Plain self-builds compile the full `cmd/v` CLI, which embeds and defaults to V3 on macOS,
  Linux, and BSD.
  Plain self-builds include only the C backend. Requests for an omitted backend automatically
  build and run a cached full compiler; later requests reuse it while its sources are current.
  Use `-compile-backend fastc` to include a particular backend, or `-all-backends` for all of them.
  On Apple Silicon, regular self-builds use bundled TCC by default; `CC` or `-cc` overrides it.
  On non-Windows hosts, -prod uses PGO with Clang when llvm-profdata is available.
  It builds an instrumented compiler, trains it on uncached self-compilation, then builds
  the optimized compiler. This takes longer to build the production compiler.
  Other C toolchains and failed PGO attempts use a regular production build.
  Add -parallel-cc to skip PGO and compile the generated C units in parallel.
  Explicit -no-prod-options or profile-related -cflags also skip automatic PGO.
  On macOS and Linux, `-b fastc` builds the standalone experimental V3 FastC compiler.
  `-prod` cannot be combined with `-b fastc`.
  FastC replacement builds (`xN` without `-o`) reject options that the standalone compiler
  cannot preserve across every generation.
  On macOS ARM64, `-b arm64` builds the full CLI with the native ARM64 backend.
  A C-only compiler automatically delegates this build to the full compiler.
  On Linux AMD64, `-b amd64` builds the full CLI with native code generation and ELF linking.
  Use `-compile-backend amd64 self` to include AMD64 before building without a C toolchain.
  The native build also compiles its self helper through AMD64, without an external linker.
  AMD64-built compilers use the serial frontend while native channel selection is incomplete.
  `x64`, `x86_64`, and `x86-64` remain aliases for `amd64`.
  Native builds retain the C backend and leave out FastC by default.
  Add `-d amd64_only` to build a compiler with only AMD64 code generation. It defaults
  to AMD64 and preserves its backend and profile through self rebuilds and cold helper builds.
  Other backend requests fail directly, without building a full compiler or using C fallback.
  `-compile-backend c self` or `-all-backends self`, without `-d amd64_only`, restores the
  general compiler profile through AMD64 code generation; the replacement defaults to C.
  `xN` repeats replacement builds, using the newly built compiler for the next build.
  Add `-o v_arm64` or `-o v_amd64` to keep the current compiler and write a separate executable.
  Native self-builds do not add C compiler or preallocation options, and report native
  compilation failures directly without retrying through the C bootstrap.
