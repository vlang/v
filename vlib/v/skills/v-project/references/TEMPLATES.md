# The three project templates

Read this when choosing between `--bin`, `--lib` and `--web`, or when a
template's contents need checking against the current compiler.

## --bin (default)

An executable application.

```
.editorconfig
.gitattributes
.gitignore
main.v
v.mod
```

`main.v`:

```v
module main

fn main() {
	println('Hello World!')
}
```

## --lib

A library. The entry point is named after the project, and a test is generated
alongside the function it tests.

```
.editorconfig
.gitattributes
.gitignore
<name>.v
tests/<fn>_test.v
v.mod
```

For a project named `mylib`, `mylib.v` contains:

```v oksyntax
module mylib

// square calculates the second power of `x`
pub fn square(x int) int {
	return x * x
}
```

## --web

A veb application.

```
.editorconfig
.gitattributes
.gitignore
assets/main.css
main.v
templates/index.html
v.mod
```

`main.v` opens with the veb structs:

```v
module main

import os
import veb

pub struct Context {
	veb.Context
}

pub struct App {
	veb.StaticHandler
}
```

## Checking a template against the current compiler

The templates are generated by `v new`, so their contents can change between
compiler versions. To see what the installed compiler actually produces:

```bash
v new /tmp/probe < /dev/null    # defaults, no prompt
```

Then read the files it created. Do not copy a template out of this file into a
project without checking it first.
