## Description

`v pbgen` generates V protobuf codecs and gRPC service declarations from `.proto`
schemas. It ships with `encoding.protobuf` and is the usual way to use it.

```sh
v pbgen -m kv -o kv/codec.v kv.proto
v pbgen -m kv -o kv/codec.v -grpc kv/service.v kv.proto
v pbgen -check -m mypkg api/v1/*.proto
```

Run `v help pbgen` for the options.

## Why generated code

The generator writes explicit calls into the `Packer` and `Unpacker` rather than
reflecting over the message type at run time:

```v ignore
packer.write_int32(7, msg.written)
```

A frame in that call names the field. A frame inside a generic encoder does not,
and the generated file is the artefact a reader debugs when a payload does not
arrive. The reflection API that would have been smaller is not available: V3
cannot express the generic decode a schema needs, since an explicit type argument
on a call whose type parameter comes from a field rather than from a generic
reaches `__v_comptime_unsupported_late_generic_call`.

## What it generates

For each message: a struct, an `encode`, an `encode_with`, and a `decode_<name>`.
For each service, with `-grpc`: a path constant per method, a service path, and a
handler interface.

The names follow three rules, so a reader can predict them:

- A message keeps its proto name. `GetRequest` in package `kv` becomes
  `GetRequest`. Only a name two declarations both want is qualified.
- A nested message flattens its chain: `Outer.Inner` becomes `OuterInner`.
- A one-letter capital name is refused, because V reserves those for generic
  template types.

`encoding.protobuf`'s README documents the generated shape in full.

## Options

| Option | Meaning |
| --- | --- |
| `-m <name>` | V module name for the generated files. Defaults to the first file's package, underscored. |
| `-o <file>` | Write the codec here. Defaults to stdout. |
| `-grpc <file>` | Write the service paths and interfaces here. Defaults to the codec output. |
| `-check` | Parse and resolve only, writing nothing. |
| `-v` | Report each declaration as it is resolved. |

### The module name

A generated local may not share the module's own name, and V rejects that
declaration with a diagnostic pointing at the local rather than at the module.
`pbgen` checks the name up front against the identifiers the emitter introduces
and against `protobuf`, which cannot be the module name because the file has to
import the runtime.

### Output files

An existing target is overwritten only when it carries the `Code generated by`
header, so a mistyped `-o` cannot delete hand-written source.

## Imports

Imports are followed, so a schema referring to a type declared in another file
resolves without that file being passed as well. An import is resolved against the
importing file's directory first, then the working directory.

The protobuf "well-known types" (`google/protobuf/*.proto`) are reported rather
than bundled. Those schemas are compiled into every runtime, and bundling a second
copy here would let the two drift apart. Handle such a field by hand.

## gRPC

`-grpc` emits the path constants and a handler interface. The signatures are
transport-free on purpose: no `net.grpc` type appears, so the generated file
compiles without the transport module and the adapter that registers a service is
the caller's to write.

An rpc's request and response sides follow the streaming flags independently:

```v ignore
pub interface KV {
	get(req GetRequest) !GetResponse
	put(req PutRequest) !PutResponse
	scan(req GetRequest) ![]GetResponse
	put_many(reqs []PutRequest) !PutManyResponse
}
```

`net.grpc` moves payloads as `[]u8` and never looks inside them, so only the codec
needs to know the message types.

## What is refused

Anything the generator did not fully understand is refused rather than emitted. A
codec that quietly disagreed with its producer would be worse than a failure, and
nothing downstream would catch it.

- proto2, and with it `required` and proto2 default values
- groups, the deprecated construct the spec kept for compatibility
- `extend`
- two fields on one number, a repeated field name, a field number outside
  1 to 536870911
- `packed = true` on a field with no packed form
- a one-letter capital type name

## Not honoured

Field options other than `packed` are parsed and skipped, so a schema using them
does not fail to parse. None of them change the bytes: `deprecated` and
`json_name` describe the schema rather than its encoding.

## Tests

`v test cmd/tools/vpbgen/`

The tests compile the generated output and then round-trip it: scalars, packed and
unpacked repeated fields, a map followed by another field, a nested message, a
`oneof` carrying two members, an unknown field, and a wrong wire type. Compiling
proves the text parses; the round trip proves it agrees with the wire format.
